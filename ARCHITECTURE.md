# Архитектура проекта User Management API

## Общая структура

Проект построен по слоистой архитектуре.

Основная идея разделения:

- **API** отвечает за взаимодействие с клиентом;
- **Services** содержит бизнес-логику приложения;
- **Repositories** отвечает за работу с данными;
- **Models** описывает структуру базы данных;
- **Core** содержит общие механизмы приложения;
- **DB** отвечает за подключение к внешним хранилищам.

/

# Приложение

Расположение:

```text
app/
```

Основной пакет приложения.

Содержит исходный код FastAPI приложения.

Структура:

```text
app/
├── api/
├── core/
├── db/
├── models/
├── repositories/
├── schemas/
├── services/
└── main.py
```

---

# Точка входа приложения

Расположение:

```text
app/main.py
```

Отвечает за сборку FastAPI приложения.

Основные задачи:

- создание экземпляра FastAPI;
- подключение маршрутов;
- регистрация обработчиков ошибок;

Не содержит:

- бизнес-логику;
- SQL-запросы;
- работу с внешними сервисами напрямую.

---

# API слой

Расположение:

```text
app/api/
```

Слой взаимодействия с клиентом.

Отвечает за HTTP-часть приложения.

Основные задачи:

- обработка HTTP-запросов;
- проверка входных данных;
- вызов сервисов;
- формирование HTTP-ответов;
- работа с зависимостями FastAPI.

Не содержит:

- бизнес-логику;
- SQL-запросы;
- работу с базой данных напрямую.

---

# Core

Расположение:

```text
app/core/
```

Слой общих механизмов приложения.

Содержит:

- конфигурацию приложения;
- JWT-аутентификацию;
- хэширование паролей;
- подключение Redis;
- пользовательские исключения;
- обработчики ошибок.

Используется другими слоями приложения.

Не содержит:

- HTTP-логику;
- SQL-запросы;
- бизнес-сценарии приложения.

---

# Обработка ошибок

Расположение:
```text
app/core/exception_handlers.py
```

Отвечает за преобразование внутренних исключений приложения в HTTP-ответы FastAPI.

Позволяет отделить бизнес-ошибки от HTTP-логики.

---

# DB

Расположение:

```text
app/db/
```

Слой подключения к базе данных.

Отвечает за работу с PostgreSQL через SQLAlchemy.

Содержит:

- создание асинхронного подключения;
- настройку SQLAlchemy Engine;
- создание AsyncSession;
- базовый класс моделей.

Не содержит:

- SQL-запросы;
- бизнес-логику;
- правила приложения.

---

# Models

Расположение:

```text
app/models/
```

Слой описания структуры данных.

Содержит SQLAlchemy модели.

Отвечает за:

- описание таблиц PostgreSQL;
- типы колонок;
- ограничения модели.

Не содержит:

- SQL-запросы;
- бизнес-логику;
- HTTP-логику.

---

# Repositories

Расположение:

```text
app/repositories/
```

Слой доступа к данным.

Отвечает за взаимодействие с базой данных.

Основные задачи:

- выполнение запросов через SQLAlchemy;
- получение данных;
- сохранение данных;
- CRUD операции.

Использует:

- SQLAlchemy;
- модели базы данных;
- сессии PostgreSQL.

Не содержит:

- JWT;
- HTTP-логику;
- бизнес-правила.

---

# Services

Расположение:

```text
app/services/
```

Слой бизнес-логики приложения.

Отвечает за пользовательские сценарии.

Основные задачи:

- регистрация пользователей;
- авторизация пользователей;
- проверка бизнес-правил;
- подготовка данных для работы с репозиториями.

Использует:

- repositories;
- механизмы безопасности;
- исключения приложения.

Не зависит напрямую от:

- HTTP;
- FastAPI;
- деталей хранения данных.

---

# Schemas

Расположение:

```text
app/schemas/
```

Слой описания контрактов данных.

Использует Pydantic.

Отвечает за:

- проверку входных данных;
- описание структуры запросов;
- описание структуры ответов;
- преобразование данных между JSON и Python-объектами.

Не содержит:

- SQLAlchemy;
- бизнес-логику;
- работу с базой данных.

---

# Alembic

Расположение:

```text
alembic/
```

Система управления миграциями базы данных.

Отвечает за:

- создание миграций;
- применение изменений структуры PostgreSQL;
- контроль версии базы данных.

Не используется для:

- выполнения обычных запросов;
- бизнес-логики приложения.

# Docker

## Dockerfile

Отвечает за создание образа приложения.

Выполняет:

- выбор базового Python-образа;
- установку зависимостей;
- копирование исходного кода;
- настройку запуска приложения.

---

## docker-compose.yml

Описывает запуск контейнеров приложения.

Используемые сервисы:

```text
app
postgres
redis
```

Назначение:

| Сервис | Назначение |
|---|---|
| app | FastAPI приложение |
| postgres | основная база данных |
| redis | хранение временных данных и ограничения запросов |

---

## entrypoint.sh

Сценарий запуска контейнера приложения.

Выполняет:

1. применение миграций базы данных;
2. запуск FastAPI приложения через Uvicorn.

# Принципы архитектуры

В проекте используются следующие принципы:

- разделение ответственности между слоями;
- отсутствие бизнес-логики в HTTP-слое;
- отсутствие SQL-запросов в сервисах;
- централизованная конфигурация через переменные окружения;
- использование асинхронного доступа к базе данных;
- изоляция доступа к данным через Repository Pattern.

Такое разделение упрощает поддержку проекта, тестирование отдельных компонентов и дальнейшее расширение функциональности.
